# Marketplace

## Purpose

The OpenBot Marketplace should distribute reusable working intelligence, not only prompts.

## Package Categories

- Agents / workers
- Decks
- Skills
- Tools
- MCP integrations
- Brains
- Memory packs
- Workflows
- Policies
- Triggers
- Evaluators
- Datasets
- Runtime adapters
- Harness adapters
- themes/extensions where appropriate

## Core Actions

- discover
- install
- update
- publish
- fork
- remix
- version
- benchmark
- share

Potential future monetization:
- free
- one-time purchase
- subscription
- per-run
- revenue share

Do not expose monetization as available before it is implemented.

## Evidence Over Marketing

Listings should eventually include:

- version
- author
- compatibility
- required permissions
- dependencies
- model compatibility
- harness compatibility
- runtime requirements
- verified runs
- task success
- cost
- latency
- human intervention
- evaluation suite
- changelog

## Ecosystem Goal

Retention should come from value and network effects:
- reputation
- creator history
- verified performance
- purchased components
- team/private packages
- run/eval history
- compatibility
- community
- cloud/runtime convenience

Avoid artificial lock-in.

## Trust

Marketplace packages must make risk visible.

At minimum, packages should declare:
- filesystem access
- network access
- secrets required
- tools used
- external services
- code execution
- expected cost
- approval requirements

High-risk packages should never be one-click opaque execution.
